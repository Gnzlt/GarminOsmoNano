# GarminOsmoNano: agent rules

This repo (GarminOsmoNano) holds **OsmoNano**, a Garmin Connect IQ **watch app** in Monkey C. It
controls a **DJI Osmo Nano** over the watch's own BLE: start/stop recording, take a photo, pick the
shooting mode, and show the link state, the recording state and its time.

The Nano speaks the **DUML** protocol over BLE, as documented by the open-source projects credited
in [`THIRD_PARTY_NOTICES.md`](THIRD_PARTY_NOTICES.md); the subset used here is described in the
headers of `source/duml/` and `source/camera/NanoSession.mc`. It works on a Nano at the watch's
20-byte BLE limit (field test, 2026-10-06). The Protocol menu's choices stay for other firmware, and
every frame is logged.

For anything about the Connect IQ platform, look it up in Garmin's developer docs
(<https://developer.garmin.com/connect-iq/>).

## Hard rules

- **Never sideload to the watch, upload to the Connect IQ Store (beta included), or publish
  anything without asking first.** Building locally is always fine.
- **The developer key never enters the repo.** It lives at
  `~/.config/connectiq/developer_key.der`, or at `$CIQ_KEY`; `*.der` and `*.pem` are gitignored.
  Every Store upload is signed with the same key, or the Store refuses it.
- No `.prg`, `.iq`, `.fit` or `bin/` output is committed. Logs off the watch go in the gitignored
  `logs/`: they hold the camera's address and serial.
- **Commit every step** of a change separately, once it passes the gate, and push it to `main`,
  so the history reads as the work went.
- **The app has a Store beta**, under its own app id (`BETA_ID` in `scripts/build.sh`), and every
  version ships as both packages, release and beta, at the same version.

## Products

OsmoNano ships for the Garmin watches whose device profile shows all of these:

- BLE for apps (the app talks BLE);
- a round or semi-octagon screen (rectangular ones are not drawn for);
- Connect IQ 3.2.7 or later (`minApiLevel`): some part numbers of the Instinct 2, the Descent G1
  and the fēnix 5 Plus run 3.2.7 or 3.2.8, and the Store package drops what the level does not cover;
- at least 96 KB for a watch app, the Instinct 2's limit;
- START and BACK. UP, DOWN and MENU are optional: a touch-first watch (Venu, vívoactive) has no UP
  and DOWN, so the app takes swipes and a long press there.

That is 83 products: fēnix 5 Plus, 6, 7, 8, 9 and E, epix 2 / Pro, Enduro 3, Descent Mk2 / Mk2S /
G1, Forerunner 55, 165, 245, 255, 265, 570, 745, 945, 955, 965 and 970, Instinct 2, Crossover, E and
3, MARQ 2, D2 Mach, Venu, Venu 2, 3 and 4, and vívoactive 4, 5 and 6. Bike computers (Edge) are out.

- `scripts/devices.py` holds the candidates and checks each against its SDK device profile; a
  missing profile is reported, never assumed. To add a watch: add it to `CANDIDATES`,
  `uv run --no-project python scripts/devices.py --manifest` (it also writes `minApiLevel`), then
  `scripts/icons.sh`, then look at the demo on it.
- Layouts are proportional to the screen (round, 156 to 466 px; AMOLED and MIP).
  After a UI change, check the largest (454 px, fenix847mm), the smallest round (208 px, fr55) and
  one Instinct (instinct2, with its subscreen).
- `onUpdate` only draws. Geometry, fonts, bitmaps and strings are worked out once per layout or
  settings change; never call `loadResource` or measure text per frame. In AMOLED low power
  (`System.getDisplayMode()`), draw no static bright shapes.

## Resources

- `resources/main/`: the hand-written resources (strings, settings, drawables), the base every
  product falls back to. `resources/main/strings/version.xml` is written by every build from
  `VERSION`.
- `resources/gen/`: generated by `scripts/icons.sh` and never edited by hand. `round-WxH/` holds
  art per screen size, `<product>/` the launcher icon at that product's size and its UI flags
  (`strings/ui.xml`). They are committed, so a clone builds without the image tools.
- Connect IQ finds qualifier folders only next to the base folder, so `scripts/jungles.py` names
  each product's `resources/gen/` folders in `monkey.jungle` and `beta.jungle`, between the
  generated markers.

## Build

The toolchain is the Connect IQ SDK's `monkeyc`, `monkeydo` and `connectiq` (SDK 9.3.0 or later;
the fēnix 8 needs API 6.0.3). Python runs through `uv`. On headless Linux, `ciq-sim` runs the
simulator on a virtual display.

```sh
scripts/build.sh            # release bin/OsmoNano-<product>.prg for every product, and bin/OsmoNano-test.prg
DEVICE=fenix847mm scripts/build.sh   # one product only (and the test build on it)
scripts/build.sh --demo     # also bin/OsmoNano-demo.prg, the demo build (no BLE needed)
scripts/build.sh --iq       # also bin/OsmoNano.iq and bin/OsmoNano-beta.iq: always both (--beta is the same)
scripts/test.sh             # every unit test, in a fresh simulator
scripts/icons.sh            # resources/gen/, the launcher icons, store/icon-500.png and store/hero.png
ciq-sim run bin/OsmoNano-demo.prg fr255sm   # the demo on one device, headless
```

**The gate, for every change:**

1. `scripts/build.sh` compiles every product and the test build with strict type checking
   (`-l 3`) and **no warnings**.
2. `scripts/test.sh` passes every test.
3. After a UI change: build `--demo`, run it on the devices above, take `ciq-sim shot`
   screenshots and look at each screen.

### Test and simulator quirks

- The simulator has no BLE, so BLE code is checked on the watch; pure logic is unit tested
  behind a fake transport.
- A failed `Test.assert` shows as `ERROR` with no message in `ciq-sim test`. Bisect with smaller
  tests rather than looking for a stack trace.
- The simulator is restarted for every test run: one that still holds the app's BLE profiles
  from an earlier run crashes in `registerProfile` or hangs `monkeydo`.
- `System.println` does not reach `monkeydo` outside test runs.
- Simulator menus open as separate X windows that `ciq-sim shot` does not capture: take an
  `xwd -root` screenshot of display `:77`.
- The simulator keeps the first device it ran: `ciq-sim stop` before running another.

## Versions and the Store

- `VERSION` holds the app version (semver: `0.x.y` for betas, `1.0.0` for the first public
  release). Bump it before every Store upload: the Store refuses a version it has seen. Add the
  version's entry to `CHANGELOG.md`, in words a user follows, and rewrite `store/whatsnew.txt`, the
  text the upload form's "What's new" field takes, for that version alone: plain ASCII, a few short lines
  that a user updating the app reads in seconds (what is new, in plain words). Update `store/description.txt` too when what the app
  does or the watch list changes.
- `store/` holds everything an upload asks for, committed: `listing.md` (the form's fields and the
  upload steps), `description.txt` (the plain-text description to paste), `whatsnew.txt` (the
  version's update note to paste), `icon-500.png` and
  `hero.png` (rendered by `scripts/icons.sh` from their sources), and `screens/*.jpg`.
- Store screenshots come from the demo build: `ciq-sim shot store/screens/raw/<name>.png` (raw
  captures are gitignored), then
  `uv run --no-project --with pillow python scripts/screens.py store/screens/raw/<name>.png
  store/screens/<n>-<name>.jpg`. The Instinct's window leaves a black strip to crop first.
- After an upload, tag the commit: `git tag v<VERSION> && git push --tags`.

## Style

- Monkey C with explicit types on every member, parameter and return (strict type check).
- Indentation of 4 spaces. Classes are `PascalCase`; members and functions are `camelCase`, with
  a leading `_` for private members.
- Comments say *why*. Each file starts with a short header saying what it owns.
- Ad-hoc experiments go in `scratch/`, which is gitignored.

## OsmoNano

- The app is called `OsmoNano` on the watch, in the build outputs (`bin/OsmoNano-*.prg`) and in
  the log file (`OSMONANO.TXT`); the repo is GarminOsmoNano.
- App type `watch-app`, permission `BluetoothLowEnergy`. 96 KB at the least (Instinct 2 family),
  128 KB on the Instinct E / 3 Solar, fēnix 6, Forerunner 55 and 245, 512 KB on the Forerunner 255,
  768 KB to 1.25 MB elsewhere.
- **Per-watch UI flags.** `devices.py` works out START's angle, `mono` (black and white only: the
  Instinct), `nogrey` (a few colours and no grey: the Forerunner 55) and `touch` (no UP and DOWN:
  Venu, vívoactive). `scripts/icons.sh` writes them into `resources/gen/<product>/strings/ui.xml`
  as the `UiFlags` string (default in `strings.xml`), and `source/ui/Ui.mc` reads them once at start.
  `MainView.paint()` turns colours white, or greys white, for the first two.
- **Subscreen** (Instinct): `WatchUi.getSubscreen()` gives the round window at the top right,
  which has a ring around it that the simulator draws bigger than the window. `MainView` keeps the
  top line beside it (dropping the link bars, and shortening the phase words, if they don't fit),
  puts START's mark inside it, and moves the mode name, waiting text and picker under its ring.
- **Touch watches:** `onSwipe` passes through only when `Ui.touch`; the behaviour then maps a swipe
  to next or previous page, and a long press to the menu (Venu 4 and vívoactive 6 have no MENU key).
  Taps stay swallowed. `ciq-sim` sends mouse clicks and swipes straight to the START, UP and DOWN
  behaviours and never calls `onTap` or `onSwipe`, so the simulator cannot show this; a tester can.
- **Never send a shooting-mode value outside `Nano.MODES`**: sweeping unknown values froze a Nano.
- The repo is public (MIT). `docs/` holds the maintainer's working notes and is gitignored.
- Pixel sizes go through `MainView.px()`. The mode art is drawn per screen size into
  `resources/gen/round-WxH/` by `scripts/mode-icons.py`; the launcher icon's master comes from
  `assets/icon-source.jpg` (`scripts/icons.py`).
- In the simulator on fenix847mm, the buttons are at fixed window positions: hold UP (30,445) for
  the menu, DOWN (55,605), START (685,300). The real app stays on "Choose camera", with an empty
  list. The demo build walks every screen in a 60-second loop.
- Diagnostics: the **Diagnostics** screen (menu) shows the frame log live; `source/Log.mc` also
  writes every line to `OSMONANO.TXT` when that file exists on a sideloaded install.
  `source/RunTrail.mc` keeps one record in Storage per run (clean stop or not, uptime, peak and
  least-free memory, link phase), so the next launch logs how the last one ended: a watch app has
  no FIT file for this, and a Store or beta install writes no text log. Writes to Storage go
  through `Store` (`source/Store.mc`), which cannot throw: an exception in a BLE callback ends the
  app.

### BLE and DUML rules

These come from the Nano's behaviour, as recorded by KonradIT. Breaking one fails on the camera, not
in the compiler.

- **One GATT operation in flight;** writes are split into 20-byte chunks (the Connect IQ maximum).
- **The GATT setup has three steps:** the CCCDs of both `FFF4` and `FFF5`, then `01 00` written to
  the `FFF4` value with response, then about 200 ms of settling. Without them, the camera ACKs
  writes at the ATT level and answers nothing.
- **Frames are at least 120 ms apart.** `FFF5` is write-without-response, and back-to-back writes
  are dropped. Answers to the camera's requests go ahead of the queue.
- **Answer every camera request** (flags `0x40`) once: flags `0xC0`, same seq, source and
  destination swapped. Unanswered, the camera drops the link.
- **A keepalive every second,** or the Nano drops the link after 5–6 s.
- **Notifications arrive cut to 20 bytes:** frames longer than that are delivered as partial (the
  header is checked, the payload is what arrived). A decoder returns null for a field whose bytes
  did not arrive. Never guess.
- **Recording state comes only from the camera's status** (push or `02/70` poll), never from a
  command's reply. It is read only from the full status form (37+ bytes) in video work mode
  (`flags & 0xC0`); the compact form's bit `0x40` is the dock.
  `0x02/0x02` is not a toggle.
